Hybrid 3D patch visualization
============================

``BlockGraph.view_patches_as_html`` expands a block diagram into stacked
surface-code rounds. Each ordinary cube contains ``d = 2*k + 1`` rounds,
including initialization and final readout. Spatial pipes show the physical
bridge and changed boundary stabilizers generated by the compiler.

Memory and lattice surgery
--------------------------

The returned viewer displays directly in a notebook. It can also be saved as
HTML and opened in a browser. Like the existing block viewer, the HTML loads
Three.js from a CDN and needs network access for those JavaScript modules.

.. code-block:: python

    from tqec.gallery.memory import memory
    from tqec.gallery.cnot import cnot
    from tqec.utils.enums import Basis

    memory(Basis.Z).view_patches_as_html(k=2)  # distance 5

    graph = cnot(Basis.Z)
    graph.view_patches_as_html(k=1, write_html_filepath="cnot_patches.html")

The scene opens with the complete stack. Use the round controls to isolate a
round or interval, and adjust layer spacing and opacity to inspect the interior.
The observable selector chooses a correlation surface. Separate overlays show
its logical Pauli support, stabilizers added or removed between rounds, and the
stabilizer factors relating logical representatives. Tooltips give qubit
coordinates, Pauli support, and measurement-record contributions.

To choose a compilation convention or an explicit observable:

.. code-block:: python

    from tqec.compile.convention import FIXED_BOUNDARY_CONVENTION

    surface = graph.find_correlation_surfaces()[0]
    graph.view_patches_as_html(
        k=1,
        convention=FIXED_BOUNDARY_CONVENTION,
        observables=[surface],
    )

Pass ``observables=None`` to display geometry and measured stabilizers without
logical overlays. Check polygons represent measurements performed in a round;
transition layers can have different input and output supports. Additional
Hadamard realignment rounds appear separately between cube stacks.

Partially supported computations
--------------------------------

Unsupported physical operations retain their block-level appearance. For
example, an open CNOT can be inspected without filling its input/output ports:

.. code-block:: python

    open_cnot = cnot()
    open_cnot.view_patches_as_html(k=1, write_html_filepath="open_cnot.html")

Conditional cubes and unsupported Y or Hadamard operations also remain visible.
The viewer preserves the original topology and does not select conditional
branches or supply artificial input states.

Fallback includes the boundary affected by an unsupported operation. An
unsupported spatial operation keeps its connected surgery region in that time
slice coarse. A temporal interface keeps the touching round as a thin coarse
slab, while the other rounds of the neighboring stack remain physical. This
avoids depicting an artificial initialization or final measurement.

Correlation surfaces remain topological where physical tracking is unavailable
and become logical operators where local circuit flows can be verified. Amber
endpoint markers identify where a physical trace meets an unavailable interval;
their tooltips explain the boundary. A
stabilizer difference is never inferred across an unsupported interval. If
automatic correlation discovery is unavailable, the geometry remains usable and
the viewer explains the limitation; explicit partial surfaces and stored
conditional surfaces can still be displayed.

Round labels identify the original block-time slice and local round. Unknown
operations retain their diagram placement, but their physical duration and
global cycle offsets across them are unspecified.

This visualization does not extend the capabilities of
``compile_block_graph``. Circuit compilation retains its existing validation and
unsupported-operation errors. The viewer runs without detector discovery or
detector-database writes and does not modify the supplied graph.
